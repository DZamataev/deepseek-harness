# Agent Note: Composer prediction

Status: implemented

[English](2026-10-20-composer-prediction.md) | 中文

## 问题

Agent 回复之后，用户的下一条消息往往可以预料："跑一下测试"、"提交吧"、"可以，继续"。输入这些内容需要时间，而 Web 输入框在用户开始输入前什么也不提供。Hermes 以输入框幽灵文本的形式提供此功能：一个轮次完成后，Agent 自己的模型借助已预热的提示缓存猜测用户的下一条消息，空输入框以幽灵文本显示该猜测，Tab 或右方向键把它填入草稿而不发送。

DSH 没有其他对应功能，输入框也没有为此提供其他扩展点。`dsh-client-ui-conversation` 中的常驻输入框在内部组合占位文本，并且只通过触发菜单键位映射处理 Tab。插件可以通过 `inputActions.setDraft` 写入草稿，但无法在空输入框中显示建议，也无法为建议占用 Tab 和右方向键。

## 决策

该功能以可选的实验性 bundle 交付，建立在一个新的产品接缝之上。该接缝保持中立：它只知道输入框建议，不知道模型预测。

### Host 插件：`@deepseek-ai/dsh-experimental-composer-prediction`

**触发。** 插件观察提交后的 `session/event` 事件流。当某个 `turn/end` 的原因为 `completed` 时，为该轮次规划一次预测。以下情况跳过：子 Agent 会话；助手消息少于 `minAssistantMessages` 的对话；最后一条消息不是助手回复或带有工具调用的轮次；最后一条助手消息未上报用量的轮次；以及估算的未缓存输入超过 `maxUncachedTokens` 的轮次。该估算读取最后一条 `assistant/message` 的用量——上报了缓存读取时只计其输出 token，未上报时计整个提示词——因此该上限约束的是估算值，而不是提供方的账单：低于上限的冷请求仍会被发送。

**请求。** 该请求以与默认压缩摘要器相同的方式复用提供方已预热的前缀缓存：在会话自身的提供方和模型上逐字节重放会话派生的消息（从表面节点 0 的系统头开始）、`maxTokens` 被替换为 `maxOutputTokens` 的已记录 `requestHeader().config`、已记录的工具以及 `Session.toolHistory()`，然后追加一条携带预测指令的用户消息。指令要求给出用户接下来会输入的消息，使用用户的语言和风格，2 到 12 个词，绝不使用助手的口吻，当下一步不明显时输出 `NONE`。该调用设置 `purpose: 'composer-prediction'`，并将输出上限设为 `maxOutputTokens`。它只尝试一次。工具调用、`max-tokens` 结束、错误或中止都不产生建议。

**取消。** 新的 `turn/start`、插入收件箱的用户消息、Agent 释放或插件卸载会通过 `AbortSignal` 中止进行中的请求。在结果被追加前中止的请求不会记录结果。

**输出过滤。** 移植自 Hermes `reject_reason` 和 `_clean` 的规则在去除标签、角色前缀、引号和包裹标签后，接受 2 到 12 个词、少于 100 个码点的回复；单个词时，斜杠命令、`yes`、`continue` 或 `да` 之类的固定回复，以及至少两个字符的不分词文字，也会被接受。它对 `NONE` 保持沉默，并拒绝关于沉默的元文本、错误文本、待填占位符、多个句子、格式标记、赞扬或感谢以及助手口吻的开头。规则覆盖英语、俄语和不以空格分词的 CJK 文字。

**会话日志。** 两条通过 `appendPluginRecord` 追加的实验性插件记录使辅助请求无需修改会话格式即可重建：

- `plugin:composer-prediction/request`，在发送前写入：轮次、被重放的 `turn/end` 序号、提供方、模型、`maxTokens` 以及指令文本。
- `plugin:composer-prediction/result`，在回复后写入：`{ requestSeq, turn, outcome, text | null, reason?, usage? }`。

**投影。** `ctx.sessionProjections` 上的 `composerPrediction` 单元把日志折叠为最新已开始轮次的 `{ turn, text } | null`。该轮次带文本的已接受结果记录会设置它；新的 `turn/start`、用户消息或非空收件箱插入会清除它。客户端通过现有投影载体接收该值，因此它能在重新加载和重新连接后保留，所有客户端看到同一个值。

**配置。** `maxOutputTokens`、`timeoutMs`、`minAssistantMessages` 和 `maxUncachedTokens` 是经过校验、可在 `cordis.yml` 中设置的必填 `Config` 字段；bundle 提供 1024、60000、2 和 10000。

### 产品接缝：`dsh-client-ui-conversation` 中的输入框建议

Conversation 服务通过 `ctx.conversation.suggestions` 暴露一个根作用域注册表。它接受一个建议提供方，其 `forSession(sessionId)` 为对应会话返回可观察的 `string | undefined` 数据源，`storeFor(sessionId)` 返回一个跟随注册变化的身份稳定数据源。第二个并发的提供方注册会抛出异常，每次注册返回自己的释放函数，且永远不会撤回后来的注册。注册通过 `ctx.effect` 进行。

**可见性。** 建议只是占位文本，从不是草稿文本。当草稿为空、不存在附件或命令芯片、会话空闲且没有打开 `/` 或 `@` 菜单时，输入框显示建议。建议优先于默认占位文本和计划模式占位文本；所有者提供的占位文本（Hero、不可用、父会话离线）和引导队列提示优先于建议。输入文字会隐藏它，清空草稿后它再次出现，下一个完成的轮次会替换或清除它。输入框不提供关闭操作：输入另一条消息就是用户忽略它的方式。

**呈现。** 建议以幽灵样式渲染在占位文本的位置，末尾带有由语言包提供的 Tab 按键提示。该提示是真实按钮，因聚焦编辑器负责接受而排除在 Tab 顺序之外；点击或轻触该提示即接受建议，因此没有 Tab 键的触屏设备也能接受。编辑器通过 `aria-describedby` 引用建议及其提示。

**按键。** 接受按键只在输入框编辑器获得焦点时生效；键位映射把它们注册为 Lexical 编辑器命令，编辑器只为自身获得焦点的根元素分发这些命令。它们在触发菜单仲裁放行后运行：

- 无修饰键、不在输入法组字中的普通 Tab 或右方向键，在实时编辑器文档为空且建议可见时，通过 `setDraft` 写入建议文本，光标位于末尾。它永远不会提交。空状态检查读取 Lexical 文档而不是 React 状态，因此同一帧内输入的字符永远不会被替换。没有可见建议时，Tab 保持原生焦点切换。
- Shift+Tab、带修饰键的右方向键和 Escape 保持原有行为。

没有提供方时，输入框的行为与之前相同。

### Client 插件与 bundle

`@deepseek-ai/dsh-experimental-client-ui-composer-prediction` 注册提供方，并把每个会话的 `composerPrediction` 投影映射为其文本，带有本地线上守卫和每个会话一个身份稳定的数据源。它不拥有其他 UI。

`@deepseek-ai/dsh-experimental-composer-prediction-bundle` 插入 Host 和 Client 行，提供本地化元数据、临时实验性图标以及 README，并通过 `OPTIONAL_BUNDLES` 提供，因此插件页的“更多”列表以关闭状态显示它。不附带示例组合：`apps/cli/config/examples/` 条目需要 `apps/cli` 依赖和 `docs/user/` 指南，而 bundle 已经提供了可选路径。默认产品只组合该接缝，没有提供方时它不产生任何效果。

### 文档

每个新包的 README 都包含 Model Experience 部分：预测模型看到什么、它的 token 成本、它对 KV 缓存的影响，以及它不会给主对话的请求增加任何内容。`dsh-client-ui-conversation` 的 README 和 JSDoc 记录建议接缝。生成的目录同步刷新。

## 考虑过的替代方案

**用独立的廉价模型处理简短对话记录。** 当预测任务路由到其他提供方或模型时，Hermes 使用这条路径。每个轮次一次冷请求会失去已预热的前缀，并且只能看到最近几条消息，因此在 DeepSeek 的前缀缓存下，预测既缺少信息，按有效 token 计也并不更便宜。如果有使用方需要，以后可以在显式 `provider`/`model` 配置后增加路由路径；现在同时支持两条路径会使请求代码和测试翻倍。

**像 Hermes `complete.suggest` 那样使用 Host 内存加 Remote 读取。** 预测会在重启后消失，而辅助请求仍需记录，才能保持模型可见输入可重建。它还需要新的 Remote 命名空间以及推送或轮询通道，而会话投影已经提供了这些。

**`SessionEventMap` 中的会话事件。** 已发布的事件类型会为一个装饰性的实验值承诺持久模式和迁移义务。插件记录专门用于实验性插件自有的状态，其所有者可以丢失这些状态而不改变日志其余部分的解释方式。

**默认开启并带设置开关的产品功能。** Hermes 默认开启预测。每个完成的轮次都会多计费一次大部分已缓存的请求，而 DSH 上的预测质量尚未测量。可以在有证据后从实验组推广。

**由组件发布建议的插槽。** 插槽占用者渲染 React 组件；接受 Tab 需要在键位映射内同步获得建议文本。一个只通过 effect 发布数据的组件会把数据提供方隐藏在渲染之后，并使键位映射滞后一次提交。

## 后果

- **计费。** 每个通过跳过规则的完成轮次都可能多发出一次请求。冷缓存保护与早期对话跳过了限制成本，而不上报用量的提供方永远不会预测；缓存读取计数错误的提供方只会让该保护成为估算。
- **缓存一致性。** 重放复用压缩摘要器的重建逻辑，因此自记录请求以来的请求派生差异或工具声明变化会未命中缓存并按全价计费。该保护无法提前发现这种偏差，因为只有提供方的答复才会揭示它。
- **预测质量。** 错误的猜测没有代价：输入文字即可替换它，任何猜测都不会被自动发送。过滤规则和 `NONE` 指令倾向于保持沉默，因此常见的失败是漏掉预测而不是给出糟糕的预测。
- **Tab 占用。** 只有在建议可见时，在聚焦的空输入框中占用普通 Tab 才会移除编辑器的向前焦点切换；键盘用户仍可用 Shift+Tab 离开，提示按钮覆盖触屏设备。
- **单一提供方。** 注册表只接受一个提供方，因此每个 Client 树只能存在一个建议来源；第二个注册会明确失败，而不是静默胜出。
- **没有提供方时。** 没有提供方时输入框保留自己的占位文本和 Tab 焦点切换，因此在 bundle 或组合注册提供方之前，该接缝不改变任何行为。

## 测试

- 单元测试覆盖输出过滤规则、跳过规则与冻结请求、投影折叠以及指令字面量。
- `tests/composer-prediction.e2e.ts` 中的 Loader 组合测试通过生产配置启动测试 `cordis.yml`，只模拟 LLM 适配器，并断言第二个完成轮次后有一条请求记录和一条结果记录，重放消息是最后一次路由请求的前缀，后接该回复与指令。
- `snapshots/sdk/composer-prediction/` 中的无密钥录制会话快照通过随包发布的 SDK 配置重放辅助请求。
- Client 测试覆盖聚焦编辑器的接受、未聚焦编辑器、同帧输入、清空后重新出现、输入法组字、打开的触发菜单以及无提供方路径。
