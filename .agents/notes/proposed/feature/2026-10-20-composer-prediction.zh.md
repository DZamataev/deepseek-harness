# Agent Note: Composer prediction

Status: proposed

[English](2026-10-20-composer-prediction.md) | 中文

## 问题

Agent 回复之后，用户的下一条消息往往可以预料："跑一下测试"、"提交吧"、"可以，继续"。输入这些内容需要时间，而 Web 输入框在用户开始输入前什么也不提供。Hermes 以输入框幽灵文本的形式提供此功能：一个轮次完成后，Agent 自己的模型借助已预热的提示缓存猜测用户的下一条消息，空输入框以幽灵文本显示该猜测，Tab 或右方向键把它填入草稿而不发送。

DSH 没有对应功能，输入框也没有为此提供扩展点。`dsh-client-ui-conversation` 中的常驻输入框在内部组合占位文本，并且只通过触发菜单键位映射处理 Tab。插件可以通过 `inputActions.setDraft` 写入草稿，但无法在空输入框中显示建议，也无法为建议占用 Tab 和右方向键。

## 提案

该功能以可选的实验性 bundle 交付，建立在一个新的产品接缝之上。该接缝保持中立：它只知道输入框建议，不知道模型预测。

### Host 插件：`@deepseek-ai/dsh-experimental-composer-prediction`

**触发。** 插件观察提交后的 `session/event` 事件流。当某个 `turn/end` 的原因为 `completed` 时，为该轮次安排一次预测。以下情况跳过：子 Agent 会话；助手消息少于 `minAssistantMessages` 的对话；最后一条助手消息带有工具调用的轮次；最后一次请求从提供方缓存读取过少的轮次：当最后一条 `assistant/message` 用量估算出的未缓存输入超过 `maxUncachedTokens` 时，重放将按全价计费。

**请求。** 该请求以与默认压缩摘要器相同的方式复用提供方已预热的前缀缓存：在会话自身的提供方和模型上逐字节重放表面节点 0 的系统头、表面消息、最新 `request/header` 的工具以及 `Session.toolHistory()`，然后追加一条携带预测指令的用户消息。指令要求给出用户接下来会输入的消息，使用用户的语言和风格，2 到 12 个词，绝不使用助手的口吻，当下一步不明显时输出 `NONE`。该调用设置 `purpose: 'composer-prediction'`，并将输出上限设为 `maxOutputTokens`。它只尝试一次。工具调用、`max-tokens` 结束、错误或中止都不产生建议。

**取消。** 新的 `turn/start`、插入收件箱的用户消息或插件卸载会通过 `AbortSignal` 中止进行中的请求。轮次被取代后才到达的结果永远不会被记录。

**输出过滤。** 移植自 Hermes `reject_reason` 和 `_clean` 的规则仅在回复去除标签、角色前缀、引号和包裹标签后为 2 到 12 个词且少于 100 个字符时接受它。它拒绝 `NONE`、关于沉默的元文本、错误文本、待填占位符、多个句子、格式标记、赞扬或感谢以及助手口吻的开头。规则覆盖英语、俄语和不以空格分词的 CJK 文字。

**会话日志。** 两条通过 `appendPluginRecord` 追加的实验性插件记录使辅助请求无需修改会话格式即可重建：

- `plugin:composer-prediction/request`，在发送前写入：指令文本、提供方、模型、`maxTokens` 以及最后一个被重放的事件序号。
- `plugin:composer-prediction/result`，在回复后写入：`{ requestSeq, turn, text | null }` 以及上报的用量。

**投影。** `ctx.sessionProjections` 上的 `composerPrediction` 单元把日志折叠为 `{ turn, text } | null`。带文本的结果记录设置它；`turn/start` 和新的用户消息清除它。客户端通过现有投影载体接收该值，因此它能在重新加载和重新连接后保留，所有客户端看到同一个值。

**配置。** `maxOutputTokens`、`timeoutMs`、`minAssistantMessages` 和 `maxUncachedTokens` 是经过校验、可在 `cordis.yml` 中设置的 `Config` 字段。

### 产品接缝：`dsh-client-ui-conversation` 中的输入框建议

一个 Client 服务接受一个建议提供方，它为每个会话提供可观察的 `string | undefined` 建议。第二个并发的提供方注册会抛出异常。注册返回其释放函数，并通过 `ctx.effect` 进行。确切的注册形式——按会话解析的根作用域提供方，或按会话作用域注册——在规划阶段对照 Client 作用域 API 确定。

**可见性。** 建议只是占位文本，从不是草稿文本。当草稿为空、不存在附件或命令芯片、会话未在运行且没有打开 `/` 或 `@` 菜单时，输入框显示建议。建议优先于默认占位文本和计划模式占位文本。所有者提供的占位文本（Hero、不可用、父会话离线）和引导队列提示优先于建议。输入文字会隐藏它，清空草稿后它再次出现；下一个完成的轮次会替换或清除它。输入框不提供关闭操作：输入另一条消息就是忽略它的方式。

**呈现。** 建议以幽灵样式渲染在占位文本的位置，末尾带有由语言包提供的 "Tab" 按键提示。点击或轻触该提示即接受建议，因此没有 Tab 键的触屏设备也能接受。编辑器通过 `aria-describedby` 引用建议及其按键提示。

**按键。** 接受按键只在输入框编辑器获得焦点时生效；键位映射把它们注册为 Lexical 编辑器命令，编辑器只为自身获得焦点的根元素分发这些命令。它们在触发菜单仲裁放行后运行：

- 不在输入法组字中、实时编辑器文档为空且建议可见时，无修饰键的 Tab 或右方向键通过 `setDraft` 写入建议文本，光标位于末尾。它永远不会提交。空状态检查读取 Lexical 文档而不是 React 状态，因此同一帧内输入的字符永远不会被替换。没有可见建议时，Tab 保持原生焦点切换。
- Shift+Tab、带修饰键的右方向键和 Escape 保持现有行为。

没有提供方时，输入框的行为与现在完全相同。

### Client 插件与 bundle

`@deepseek-ai/dsh-experimental-client-ui-composer-prediction` 注册提供方，并把每个会话的 `composerPrediction` 投影映射为其文本。它不拥有其他 UI。

`@deepseek-ai/dsh-experimental-composer-prediction-bundle` 插入 Host 和 Client 行，提供本地化元数据、按 `dsh-official-plugin-artwork` 审核的官方实验性图标以及 README。示例组合位于 `apps/cli/config/examples/composer-prediction/cordis.yml`。默认产品只组合该接缝，没有提供方时它不产生任何效果。

### 文档

每个新包的 README 都包含 Model Experience 部分：预测模型看到什么、它的 token 成本、它对 KV 缓存的影响，以及它不会给主对话的请求增加任何内容。`dsh-client-ui-conversation` 的 README 和 JSDoc 记录建议接缝。生成的目录同步刷新。

## 考虑过的替代方案

**用独立的廉价模型处理简短对话记录。** 当预测任务路由到其他提供方或模型时，Hermes 使用这条路径。每个轮次一次冷请求会失去已预热的前缀，并且只能看到最近几条消息，因此在 DeepSeek 的前缀缓存下，预测既缺少信息，按有效 token 计也并不更便宜。如果有使用方需要，以后可以在显式 `provider`/`model` 配置后增加路由路径；现在同时支持两条路径会使请求代码和测试翻倍。

**像 Hermes `complete.suggest` 那样使用 Host 内存加 Remote 读取。** 预测会在重启后消失，而辅助请求仍需记录，才能保持模型可见输入可重建。它还需要新的 Remote 命名空间以及推送或轮询通道，而会话投影已经提供了这些。

**`SessionEventMap` 中的会话事件。** 已发布的事件类型会为一个装饰性的实验值承诺持久模式和迁移义务。插件记录专门用于实验性插件自有的状态，其所有者可以丢失这些状态而不改变日志其余部分的解释方式。

**默认开启并带设置开关的产品功能。** Hermes 默认开启预测。每个完成的轮次都会多计费一次大部分已缓存的请求，而 DSH 上的预测质量尚未测量。可以在有证据后从实验组推广。

**由组件发布建议的插槽。** 插槽占用者渲染 React 组件；接受 Tab 需要在键位映射内同步获得建议文本。一个只通过 effect 发布数据的组件会把数据提供方隐藏在渲染之后，并使键位映射滞后一次提交。

## 验收标准

- 启用 bundle 后，在普通会话中第二个助手回复完成后，日志包含一条 `plugin:composer-prediction/request` 记录和一条匹配的 `result` 记录，并且重放的请求逐字节等于最后一次路由请求的前缀加上指令。
- 空输入框以占位文本形式显示被接受的预测和 Tab 提示；编辑器获得焦点时，Tab 和右方向键把它放入草稿而不发送，点击提示效果相同；输入文字会隐藏它，清空草稿后它再次出现，直到下一个轮次。
- 新轮次会中止进行中的预测，被取代的轮次不会记录结果；被跳过的情况不追加任何记录。
- 没有该 bundle 时，输入框行为、Tab 焦点切换和占位文本保持不变。
- 测试：输出过滤、跳过规则和投影折叠的单元测试；通过 Loader 启动测试 `cordis.yml`、只模拟 LLM 适配器的真实组合测试；提供方和投影注册的 HMR 安全释放测试；接受、编辑器未获得焦点、同帧输入、重新出现、输入法、打开的菜单以及无提供方路径的 Client 测试；辅助请求的无密钥录制会话快照。

## 风险

- **计费。** 每个完成的轮次可能多发出一次请求。冷缓存保护和早期对话跳过限制了成本，但对于不上报缓存用量的提供方，该保护只是估算。
- **缓存一致性漂移。** 如果重放与最后一次路由请求不同，例如由于历史内系统更新或工具声明变化，请求会未命中缓存并按全价计费。重放复用压缩摘要器的重建逻辑以限制偏差。
- **预测质量。** 错误的猜测没有代价：输入文字即可替换它，不安全的猜测永远不会被自动发送。过滤规则和 `NONE` 指令倾向于保持沉默。
- **Tab 占用。** 只有在建议可见时，在空输入框中占用 Tab 才会移除编辑器的向前焦点切换；键盘用户仍可用 Shift+Tab 离开。
